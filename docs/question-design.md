# 問題バンク設計

最終更新: 2026-08-30

## 目的

問題数を増やすことではなく、給与計算実務能力検定2級の各学習目標について、知識の想起だけでなく実務での適用と誤概念の修正まで確認できる問題バンクを維持する。

`database/seeders/data/questions` 以下を890問すべての正本とする。各問を学習目標へ割り当て、同じ目標を異なる角度から学べる変種として管理し、1セッション最大10問で出題する。`question-blueprint.json` は一部問題の学習設計を補うが、出自による別バンクを作るものではない。

`scripts/extract_exam_202608.py` は受領した教材を問題バンクJSONへ変換する再現可能な取り込み補助である。問題番号1〜800、4選択肢、正答、解説がすべて揃わなければ失敗し、公式資料との照合で誤りが判明した項目は補正表で明示的に置き換える。各問題の関連資料は論点別に割り当て、欠番または二重割当てがあれば生成を停止する。取り込み後の問題は他の問題と同じSeeder、選択肢再配置、監査、出題処理を通る。

```bash
python3 scripts/extract_exam_202608.py \
  docs/exam_202608.pdf \
  database/seeders/data/questions/exam-202608.json
```

提供PDFと抽出JSONは `.gitignore` と `.dockerignore` の対象とする。問題バンクは890問で一体のため、必要なJSONが欠けた状態ではSeederを失敗させ、不完全な問題数へ自動縮退しない。

## 類似問題を残す基準

同じ `concept_key` を共有していても、次の役割が異なり、測っている判断を説明できる場合は意味のある変種として残す。

- `recall`: 原則・定義を正確に想起する
- `application`: 具体的な給与・勤怠ケースへ適用する
- `boundary`: 「以上／超える」、年齢、日数など境界条件を判断する
- `misconception`: 制度間の混同など典型的な誤概念を修正する
- `workflow`: 届出・徴収・年度更新など処理順序を判断する
- `calculation`: 資料や端数処理を用いて金額を算出する

前置き、人物名、数値、選択肢順だけを変え、同じ手掛かりで正答できる問題は削除する。各学習目標には2問以上を持たせ、同じ目標内で `variant_role` を重複させない。

## 誤答から学ばせる設計

各問題は `misconception_key` で狙う誤概念を記録し、全問で正答と全体解説を表示する。選択肢ごとの誤答理由を確認できる問題では `distractor_feedback` も返すが、その有無で問題バンクを分けない。

レッスンでは同じ学習目標を1回に1問だけ出す。再受講時は未出の変種を優先し、全変種を解答済みなら最後に解いた時刻が古いものを選ぶ。単純なランダム重複排除は行わない。

## 更新手順

1. 主催者の出題範囲と公的機関の一次資料を確認する。
2. 追加・変更する学習目標、変種の役割、狙う誤概念を問題JSONまたは `question-blueprint.json` に定義する。
3. 問題JSONを更新し、選択肢ごとの誤答理由を記載する。
4. `php artisan migrate:fresh --seed` で正本からDBを再構築する。
5. `php artisan content:audit --strict` と全テストを通す。
6. 法令基準日、公式テキスト改訂、料率・税額表更新時に影響する学習目標を再レビューする。

シーダーは設計図にない問題を公開停止し、コースJSONから削除された単元・レッスンもDBから同期削除する。過去DBの残骸を公開内容として温存しない。
