# 合格へつなぐ学習設計

目的は、給与計算実務能力検定2級の初見問題を、資料を使いながら自力で解けるようにすること。XP・クラウン・読了数は学習を続けるための報酬であり、実力の証明には使わない。

## 教材と学習順序

正本567問（通常447問・初見模試120問、承認台帳の期限は後述）、112論点、問題ID、既存15レッスンの法令レビュー依存関係を維持する。学習用の並べ方を `learning-curriculum.json` に分離し、57の短い単元へ一対一で割り当てる。定時決定など、旧ラベルが広すぎる問題は、問題内容に合わせて配置する。

| 順序 | 段階                 | 目的                                         |
| ---- | -------------------- | -------------------------------------------- |
| 1    | 給与計算の地図       | 明細・締日・月次処理・賃金の意味をつかむ     |
| 2    | 勤怠から支給額へ     | 時間・休日・割増・控除を関連づける           |
| 3    | 社会保険の基本       | 対象者・保険料の月・報酬・料率を判断する     |
| 4    | 給与から引く税金     | 課税対象・扶養・税額表を使い分ける           |
| 5    | 計算をつなげる       | 複数のルールと資料を使って手取りまで計算する |
| 6    | 条件と例外を仕上げる | 基本との違いを条件で見分ける                 |

「意味から理解する」「覚える条件を整理する」「計算手順をつかむ」を単元ごとに区別する。前提単元を提示するが、模試の弱点から戻れるように強制ロックはしない。既存のレッスンURLと問題ごとの復習も継続して使える。

## 1単元の流れ

1. **例で理解する**：公開可能な通常問題から例を1つ提示し、考え方と答えを開いて確かめる。模試の専用問題を例には使わない。
2. **手助けつきで練習する**：1〜3問。基本のルールを優先し、可能な範囲で自力確認用の未出問題を2問残す。
3. **自力で確認する**：最大5問。未出の問題・重要問題を優先し、同一単元内の異なる論点を先に選ぶ。手助けなしの正解が全配信問題の80%以上で、通常問題に含まれる各論点を自力で正解してから次へ進む。未確認の論点が残る場合は、次の短い学習回でその論点を優先する。誤答・手助けがあった論点は再確認する。
4. **日を空けて確認する**：自力確認後3日から。後日も80%以上解けたときに「後日も解けた」と記録し、その後は7日で単元を再確認する。後日確認も各論点を確かめてから記録する。同日の反復はこの証拠に数えず、期限前の練習で復習日を先送りしない。

不正解や手助けを使った解答も記録する。自力確認で目安に届かなければ、同じ単元の例へ戻る。個々の問題には既存のLeitner復習を適用する。手助けつきの正解は独立した正解回数を増やさず、翌日の復習へ送る。誤答は当日の復習へ戻す。

資料集の使用は手助けに含めない。料率を暗記して当てることではなく、設問に必要な資料を選び正しく使うことを練習する。

## 採点・報酬・再開

段階と手助け利用はサーバーのセッションに保存し、クライアントの `assisted` 申告を採用しない。単元全体の手助けを表示した後の未回答問題と、表示した例と同じ問題は手助け利用へ含める。すでに自力で解答した問題はそのまま記録する。UUIDで学習回を識別し、別タブで段階を切り替えた古い画面からの解答を拒否する。関連するルートのセッションをロックし、ヒント・採点・完了の同時要求を直列化する。

正解・解説は採点後に返す。解答前の配信には含めず、例として明示した通常問題だけを教材として提示する。完了にはサーバーの解答記録が必要で、完了記録の主キーにより再送を拒否する。再表示では解答済みIDと正解数を返し、未回答から再開する。

手助けつきの初回正解は5XP。初めて自力で解いた際の通常XPは別に獲得できる。練習・自力確認・後日確認の各段階に10XPを教材版ごとに一度だけ付与する。報酬と実力の進捗は分離する。ダッシュボードの正解率から手助けつき解答を除外する。

## 模試と合格の目安

初見模試用の120問を通常学習から隔離する既存の制御を維持する。結果の誤答を短い単元へ集約し、その例へ戻るリンクを出す。合格の目安は既存の初回・本番時間の模試2回による判定を使う（各回70点以上、平均80点以上、各回の計算18点以上、各分野60%以上）。単元の自力確認を本番の合格保証にはしない。

主催者の[2級案内](https://fos.or.jp/shikaku/pc2/)を2026年10月2日に確認。2級は知識35問・計算5問の四肢択一、120分。11月試験の法令基準日は同年9月1日。公式テキスト本文との網羅性、実際の合格率・学習効果の測定は、既存監査の未検証状態を維持する。

## データ移行と運用

`php artisan migrate --force` → `php artisan content:sync`。追加移行だけで利用でき、`migrate:fresh`、学習履歴の消去、既存問題IDの変更は不要。通常のバックアップ・デプロイ手順を用いる。

追加テーブルは単元定義・問題との対応・段階別進捗・学習回の完了記録。既存解答に単元ID・学習回UUID・手助けフラグを追加する。旧履歴を自動で新単元の自力達成へ変換しないが、問題ごとの復習、XP、模試の記録は保持する。単元の引退は無効化だけ行い、履歴を削除しない。正本の同一同期は達成を保持する。問題の改訂または単元定義の変更は、関連する単元の自力判定を再確認へ戻す。教材に未承認・内容不一致などで公開不可の問題が含まれる単元は、新しい学習回を開始せず、達成数から除外する。同期全体をトランザクションにし、単元定義が不正な場合も旧教材・履歴へロールバックする。

### 公開前の既存の未解決事項

実台帳の現行567問の再確認予定日は **2026年10月1日**。10月3日の復旧で、再確認日の超過を編集者向け通知に変更した。日付超過のみでは出題・同期・本番起動を停止せず、再確認待ちとして記録する。問題本文・実台帳の確認日・予定日・承認は変更していない。未承認や内容・根拠の不一致では引き続き停止する。テスト用台帳を公開承認へ流用しない。

依存ライブラリ4パッケージを修正版へ更新し、`composer audit --locked` の指摘を解消した。開発用依存の `brace-expansion` と `js-yaml` も修正版へ更新し、`npm audit` は開発用を含めて指摘0件。CIは実装テストと依存監査の後に実台帳による公開条件を検証する。再確認日は通知として表示し、未承認・不正な日付・内容不一致などの問題でCIを失敗させる。同期コマンドは同じリリースで更新を省略する場合にも実台帳の承認と内容一致を検証する。実装の動作検証と、教材の公開条件を分けて報告する。

学習設計の参考：[IES practice guide](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)、[研究報告PDF](https://ies.ed.gov/ncee/WWC/Docs/PracticeGuide/20072004.pdf)。解答例と練習の組合せ、徐々に手助けを減らすこと、時間を空けた学習、思い出す練習を採用した。今回の57単元の構成や80%の単元目安が、本アプリで実測された効果を持つことは主張しない。

## 追加監査で残る教材上の限界

通常問題が1問しかない単元は、締日と支払日、月次処理、資格取得時決定、割増賃金の計算、月額所得税の計算、労働保険の年度更新の6つ。例と自力確認で同じ問題を使う場合があり、この確認だけでは初見への応用を証明できない。模試の専用問題を転用して不足を隠さず、条件を変えた通常問題の追加と法令レビューが必要。

今回の各論点の確認は既存の `concept_key` に基づく。旧論点ラベルが広い問題は配置を補正しているが、一つの正解をその論点全体の完全な理解とは扱わない。公式テキストとの照合、教材の再監査、学習者の誤答率・後日正答率・初見模試への伸びの測定が完了するまで、全範囲の網羅性・学習効果・合格を保証する表現は使わない。
